# ค้นหาสินค้าด้วยชื่อไทยที่พนักงานเรียกกันทุกวันไม่เจอเลย

## อาการ

พนักงานสาขาพิมพ์ชื่อที่เรียกกันหน้าร้าน — "ร็อกเก็ต", "ผักร็อกเก็ต", "ผัก" — ลงในช่องค้นหาสินค้า
ได้ผลลัพธ์ "ไม่พบสินค้าที่ตรงกัน" ทุกครั้ง ทั้งที่ของอยู่ในระบบครบ

แคตตาล็อกทั้ง 288 รายการตั้งชื่อเป็นภาษาอังกฤษล้วน (`ROCKET SALAD (ACK)`) ไม่มีชื่อไทยอยู่ในชื่อสินค้าเลยสักตัว
ช่องค้นหาเทียบตัวอักษรตรง ๆ จึงไม่มีทางเจอ

เจอทั้งในช่องค้นหาของหน้าสร้างใบขอซื้อ และช่องค้นหาบนแถบบนของแอป

## ที่คาดว่าจะเป็น

พิมพ์ชื่อที่เรียกกันทุกวันแล้วเจอของ พนักงานไม่รู้ว่าในระบบสะกดว่าอะไร และไม่ควรต้องรู้

## ทำซ้ำได้โดย

1. เข้าเดโม เลือกแบรนด์ Pizza Mania
2. ไปหน้ารายการขอสั่งซื้อ แล้วกด "สร้างรายการขอสั่งซื้อ"
3. พิมพ์ `ร็อกเก็ต` ในช่อง "ค้นหาชื่อสินค้า / รหัสสินค้า"

ได้ **"ไม่พบสินค้าที่ตรงกัน"** · พิมพ์ `ROCKET` แทน เจอครบ 4 รายการ

สามครั้งที่ค้นไม่เจอในรอบนั้นมาจากเรื่องนี้ล้วน ๆ และเป็นสาเหตุเดียวที่ทำให้ผลเป็น `completed_with_help` ไม่ใช่ `completed`

และบันทึกไว้ว่า *"พนักงานทั่วไปที่ไม่เคยอ่านคู่มืออาจไม่คิดจะลองแบบนี้ด้วยซ้ำ"*

**เจอเป็นรอบที่สามใน SC-002** คราวนี้เป็น**หัวหน้า** ไม่ใช่พนักงาน และอยู่คนละหน้า (หน้าตรวจใบขอซื้อ)
หัวหน้าพิมพ์ "โค้กซีโร่" และ "โค้ก" ไม่เจอทั้งคู่ — เรื่องนี้จึงไม่ได้ผูกกับบทบาทหรือหน้าจอใดหน้าจอหนึ่ง
แต่เป็นเรื่องของช่องค้นหาสินค้าทุกช่องในแอป

ดู `runs/2026-09-23-SC-002-manager-desktop/dev-note.md` เฉพาะส่วนภาษาไทยเท่านั้นที่นับเข้าเรื่องนี้

**เจอเป็นรอบที่สี่ใน SC-003** บนหน้า**รับสินค้าเข้า** ซึ่งเป็นหน้าที่สาม พนักงานพิมพ์ "มอสซาเรลล่า", "ชีส", "แป้ง"
ไม่เจอทั้งหมด แล้วต้องออกจากหน้าไปเปิดหน้าสินค้าคงคลังเพื่อดูว่าในระบบสะกดว่าอะไร
เรื่องนี้จึงไม่ผูกกับหน้าจอใดหน้าจอหนึ่ง — `route` เป็น `*` ตามกติกาการรวมปัญหาซ้ำใน README

**รอบที่ห้าใน SC-004** หน้าเบิก/โอนสาขา พิมพ์ "มอสซาเรลล่า" และ "แป้ง" ไม่เจอทั้งคู่
ห้า run ติดกัน สี่หน้าจอ สองบทบาท — **นี่คือเรื่องที่พบบ่อยที่สุดในแล็บ**

## ทำไมจึงจัดเป็น MISSING_FEATURE / severity blocker / risk MEDIUM

**MISSING_FEATURE ไม่ใช่ BUG** — ช่องค้นหาทำงานถูกต้องตามที่มันถูกเขียนไว้ คือเทียบกับชื่อและรหัสที่มีอยู่จริง
สิ่งที่ขาดคือช่องทางให้ของหนึ่งชิ้นมีชื่อเรียกได้มากกว่าหนึ่งชื่อ

**ไม่ใช่ TRAINING_ISSUE** แม้จะแก้ด้วยการสอนได้ เพราะการสอนคือการให้พนักงานจำคำแปลภาษาอังกฤษของผักทุกชนิด
ซึ่งเป็นการย้ายภาระจากระบบไปที่คน และ persona บอกไว้ชัดว่าคนกลุ่มนี้ไม่อ่านคู่มือ

**severity blocker** เพราะ run แรกจบลงที่ `abandoned` และเส้นทางเดียวที่ทำให้ผ่านได้คือการเดาถูกเองว่าต้องพิมพ์ภาษาอังกฤษ

**risk MEDIUM** เพราะการแก้อยู่ในขอบเขต "ค้นหา" ตามตารางใน README ไม่แตะผู้ขาย จำนวน การอนุมัติ หรือยอดสต๊อก
