# ช่องค้นหาในหน้ารับสินค้าเข้าไม่บอกว่าหาไม่เจอ เงียบเหมือนไม่ได้พิมพ์อะไรลงไป

## อาการ

พิมพ์คำที่หาไม่เจอลงช่อง "ค้นหาสินค้าเพื่อเพิ่มรายการ" ในหน้ารับสินค้าเข้า
**ไม่มีอะไรเปลี่ยนบนหน้าจอเลย** ไม่มีรายการ ไม่มีข้อความ ไม่มีสัญญาณว่าระบบได้ยิน

กล่องด้านล่างยังเขียนว่า "ยังไม่มีรายการ — ค้นหาด้านบนเพื่อเพิ่มสินค้า" เหมือนตอนยังไม่ได้พิมพ์

หน้าสร้างใบขอซื้อในสถานการณ์เดียวกันขึ้นข้อความ **"ไม่พบสินค้าที่ตรงกัน"** — สองหน้านี้ทำคนละอย่าง

## ที่คาดว่าจะเป็น

พิมพ์แล้วหาไม่เจอ ระบบบอกว่าหาไม่เจอ

## ทำซ้ำได้โดย

1. เข้าเดโม เลือกแบรนด์ Pizza Mania ไปหน้า "รับสินค้าเข้า"
2. พิมพ์ `มอสซาเรลล่า` ลงช่อง "ค้นหาสินค้าเพื่อเพิ่มรายการ (ชื่อ / รหัสสินค้า)"

หน้าจอนิ่งสนิท · พิมพ์ `mozzarella` แทน ขึ้นสองรายการทันที (CHS-01-01-001 และ CHS-01-01-010)
การค้นหาทำงานปกติ สิ่งที่ขาดคือสถานะ "ไม่เจอ"

## ทำไมจึงไม่ใช่เรื่องเดียวกับ UX-0001

`UX-0001` คือ **หาไม่เจอ** เพราะแคตตาล็อกเป็นภาษาอังกฤษ
เรื่องนี้คือ **ไม่บอกว่าหาไม่เจอ** ซึ่งจะยังผิดอยู่แม้แก้ UX-0001 เสร็จแล้ว — พิมพ์คำที่ไม่มีจริงก็ยังเงียบเหมือนเดิม

ต้นเหตุคนละตัว แก้คนละที่ ตามกติกาใน README

## ทำไมสองอย่างนี้รวมกันแล้วแย่กว่าผลบวก

พนักงานไม่ได้แค่หาไม่เจอ แต่**ไม่รู้ด้วยซ้ำว่าระบบตอบแล้ว** จึงไม่รู้ว่าควรลองคำอื่น หรือควรสงสัยว่าระบบค้าง
run นี้ตอบสนองด้วยการออกจากหน้าไปเปิดหน้าสินค้าคงคลังเพื่อพิสูจน์ว่าของมีอยู่จริงไหม
แล้วค่อยกลับมา — เป็นการเดินอ้อมทั้งรอบที่เกิดจากความเงียบ ไม่ใช่จากการหาไม่เจอ

## ทำไมจึงจัดเป็น UX_FRICTION / severity major / risk LOW

**ไม่ใช่ BUG** — การค้นหาคืนผลลัพธ์ว่าง ซึ่งถูกต้อง หน้าจอแค่ไม่ได้วาดอะไรสำหรับกรณีนั้น

**severity major** เพราะทำให้ผู้ใช้ไม่รู้สถานะของระบบเลย ซึ่งแย่กว่าการบอกข่าวร้าย
และ run นี้เสียการเดินอ้อมทั้งรอบไปกับมัน

**risk LOW** — เติมสถานะว่างหนึ่งอัน ให้ตรงกับหน้าสร้างใบขอซื้อที่ทำถูกอยู่แล้ว ไม่แตะข้อมูลใด ๆ

## ข้อสังเกตสำหรับคนที่จะแก้

หน้าสร้างใบขอซื้อมีสถานะนี้อยู่แล้ว — **ดูว่ามันทำยังไงแล้วทำให้เหมือนกัน** อย่าประดิษฐ์ใหม่
และไล่ดูช่องค้นหาสินค้าช่องอื่นด้วย (เบิก/โอน, ปรับสต๊อก) ว่าเงียบแบบเดียวกันหรือเปล่า
