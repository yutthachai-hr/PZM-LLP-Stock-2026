# กดชื่อสินค้าเพื่อดูว่าของตัวนี้คืออะไร แล้วเด้งฟอร์มแก้ไขสินค้าเต็มรูปแบบ

## อาการ

กดชื่อสินค้าในตารางหน้าสินค้าคงคลัง เด้งป็อปอัป **"แก้ไขสินค้า"** ขึ้นมาทันที
มีช่องแก้ได้ทั้งหมด: ชื่อสินค้า · SKU · บาร์โค้ด · หมวดหมู่ · หน่วยนับ · หน่วยที่แสดง
· สต๊อกขั้นต่ำ · ผู้ขาย · **รายการผู้ขายสำรองเป็นติ๊กบ็อกซ์ยาวเลื่อนได้** · ต้นทุน

พนักงานที่กดเข้ามาเพราะอยากรู้ว่า "ของตัวนี้คืออะไร เหลือเท่าไร" ไม่ได้อยากแก้อะไรสักอย่าง

## ที่คาดว่าจะเป็น

กดชื่อของแล้วเห็นว่ามันคืออะไร อยู่ที่ไหน เหลือเท่าไร เคลื่อนไหวอะไรมาบ้าง

## ทำซ้ำได้โดย

1. เข้าเดโม เลือกแบรนด์ Pizza Mania ไปหน้า "สินค้าคงคลัง"
2. กดที่ชื่อสินค้าแถวใดก็ได้ในตาราง

ได้ป็อปอัป "แก้ไขสินค้า"

## เจอสอง run โดย agent คนละตัว

**SC-005** จัดเป็นจุดที่ติดตรง ๆ: *"ไม่ใช่สิ่งที่ต้องการ เลยปิดออกมา"*

**SC-001** เจอเรื่องเดียวกันและเขียนว่า *"ตกใจนิดนึง รีบกดปิดออกมาไม่ได้แตะอะไร
กลัวไปแก้ข้อมูลเขาโดยไม่ตั้งใจ"* — แต่ตอนนั้นจัดให้ตัวเองว่าเป็นความระมัดระวังส่วนตัว ไม่ใช่ปัญหาของระบบ

สอง agent อิสระ คนละงาน คนละเวลา ตอบสนองแบบเดียวกันคือ **ตกใจแล้วรีบปิด**
นั่นไม่ใช่ความบังเอิญของใครคนหนึ่ง

หลักฐานจาก SC-001 ใช้ได้แม้ run นั้นถูกตัดสินว่าวัด UX ไม่ได้
เพราะข้อบกพร่องของ run นั้นคือสนามซ้อมไม่มีผู้ขาย ซึ่งไม่เกี่ยวกับเรื่องนี้

## ทำไมถึงสำคัญกว่าที่เห็น

หน้าจอที่ควรตอบคำถามนี้**มีอยู่แล้ว** — Stock Card ที่ `/products/:id/card`
ซึ่งบอกยอดคงเหลือ ประวัติการเคลื่อนไหว และยอดสะสม ตรงกับที่พนักงานอยากรู้ทุกข้อ
แต่เข้าถึงได้จากเมนู ⋮ ท้ายแถวเท่านั้น ซึ่งไม่มีใครเดาถูกว่าอยู่ตรงนั้น

ของที่ถูกวางไว้ให้กดง่ายที่สุด (ทั้งแถว) คือสิ่งที่พนักงานต้องการน้อยที่สุด
ส่วนของที่ต้องการมากที่สุดถูกซ่อนหลังเมนู

**แก้ไขข้อความเดิมของ Issue นี้ (23 ก.ย. หลัง SC-006):** ตอนแรกเขียนไว้ว่าพนักงานอาจเผลอแก้ข้อมูลโดยไม่ตั้งใจ
**ข้อนั้นไม่จริง** — ตรวจ DOM แล้วพบว่าทุกช่องในฟอร์มถูก `disabled` สำหรับพนักงานและหัวหน้า
ความเสี่ยงจึงไม่ใช่การแก้ผิด แต่เป็นการเสียเวลาไปกับฟอร์มที่ใช้ไม่ได้ ดู `UX-0011` ซึ่งเป็นคนละเรื่องแต่เกี่ยวกัน

## ทำไมจึงจัดเป็น UX_FRICTION / severity major / risk LOW

**ไม่ใช่ BUG** — ป็อปอัปทำงานถูกต้องตามที่ถูกเขียนไว้

**severity major** เพราะทางที่ชัดที่สุดพาไปผิดที่ — ไปยังฟอร์มที่คนกดส่วนใหญ่ใช้อะไรไม่ได้เลย
ขณะที่หน้าจอซึ่งตอบคำถามของพวกเขาถูกซ่อนไว้หลังเมนู

**risk LOW** — ทางแก้อยู่ที่ว่าการกดแถวพาไปไหน ไม่แตะข้อมูล ไม่แตะสิทธิ์ ไม่แตะจำนวน

## ข้อสังเกตสำหรับคนที่จะแก้

**อย่าเอาความสามารถในการแก้ไขออก** หัวหน้ากับแอดมินยังต้องใช้
สิ่งที่ต้องเปลี่ยนคือ *อันไหนอยู่ปลายนิ้ว* — Stock Card ควรเป็นสิ่งที่ได้จากการกดแถว
ส่วนการแก้ไขย้ายไปอยู่ในเมนู ⋮ ที่ Stock Card เคยอยู่

ดูด้วยว่ามุมมองการ์ดบนมือถือกดแล้วไปไหน — จะทดสอบในรอบมือถือ
