# คำตัดสินหลัง reproduce

| จุดที่ติด | ผล reproduce | เป็น Issue ไหม |
|---|---|---|
| 1. ช่วงวันที่เริ่มต้นไม่มีป้ายบอกว่าคือช่วงอะไร | **REPRODUCED** | ใช่ → `UX-0013` |
| 2. ไม่มีการเทียบเดือนต่อเดือน | **REPRODUCED** | รวมใน `UX-0013` |
| 3. กล่องข้อมูลเชิงลึกหายเงียบตอนไม่มีข้อมูล | **REPRODUCED** | ใช่ → `UX-0014` |

## ข้อ 1 ยืนยันด้วยค่าจริงในหน้า

ค่าเริ่มต้นของช่องวันที่คือ `2026-09-10` ถึง `2026-09-23` = **14 วันล่าสุด**
ข้อความรอบ ๆ มีเพียง "ตั้งแต่วันที่ ถึงวันที่ สาขา ประเภทสินค้า" — ไม่มีอะไรบอกว่าเป็นช่วงอะไร

**หน้าสั่งซื้อในแอปเดียวกันมีปุ่ม "7 วันล่าสุด / 30 วันล่าสุด / 90 วันล่าสุด" อยู่แล้ว**
หน้ารายงานซึ่งช่วงเวลาสำคัญที่สุดกลับเป็นหน้าที่ไม่มี — รวมข้อ 1 กับข้อ 2 เป็นเรื่องเดียวเพราะเป็นการจัดการช่วงเวลาทั้งคู่

## ข้อ 3 ยืนยันด้วยเนื้อกล่องจริง

ตั้งช่วงเป็น 1–31 ส.ค. แล้วอ่านกล่อง "ข้อมูลเชิงลึก" ได้ข้อความทั้งหมดคือ
"ไม่มีสินค้าต่ำกว่าขั้นต่ำ ทุกรายการยังอยู่เหนือขั้นต่ำ" — บรรทัด "สินค้าที่เบิกใช้มากที่สุด" หายไปจริง

กราฟโดนัทข้าง ๆ ขึ้น "ไม่มีการเบิกใช้ช่วงนี้" ตามที่ agent เล่า ซึ่งเป็นตัวอย่างที่ถูกต้องอยู่ในหน้าเดียวกัน

## เรื่องที่ตัดสินใจไม่ตั้งเป็น Issue

ช่องวันที่เป็น `input[type=date]` ซึ่งแสดงรูปแบบตามภาษาของเบราว์เซอร์
บนเครื่องที่ทดสอบขึ้นเป็น `09/10/2026` แบบอเมริกัน ต่างจากที่อื่นในแอปที่ใช้ `23/09/2569`

**ขึ้นกับเครื่องของผู้ใช้ ไม่ใช่ของแอป** จึงไม่ตั้งเป็นเรื่อง แต่เขียนกำกับไว้ใน `UX-0013`
ว่าควรลองบนเครื่องพนักงานจริงสักครั้ง

นี่เป็นข้อจำกัดของแล็บที่ควรจำ: **เบราว์เซอร์ที่ใช้ทดสอบไม่ใช่เบราว์เซอร์ของพนักงาน**
อะไรที่ขึ้นกับภาษา เขตเวลา หรือการตั้งค่าเครื่อง ต้องแยกออกจากผลการทดสอบเสมอ

## ข้อจำกัดของ run นี้

เดโมมีข้อมูลวันเดียว รายงานที่ครอบ "เดือนนี้เทียบเดือนก่อน" จึงบางมาก
คำสั่งที่ให้ agent ระบุชัดว่าให้แยก **"หาทางไปถึงคำตอบได้ไหม"** ออกจาก **"คำตอบคืออะไร"**
และ agent ทำตามได้ดี — จุดที่ติดทั้งสามข้อเป็นเรื่องของเส้นทาง ไม่ใช่เรื่องของข้อมูลบาง
