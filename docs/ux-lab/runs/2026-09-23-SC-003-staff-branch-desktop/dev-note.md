# คำตัดสินหลัง reproduce

| จุดที่ติด | ผล reproduce | เป็น Issue ไหม |
|---|---|---|
| 1ก. ค้นชื่อไทยไม่เจอ | **REPRODUCED** | นับเข้า `UX-0001` เป็น run ที่สี่ |
| 1ข. ไม่มีข้อความบอกว่าหาไม่เจอ | **REPRODUCED** | ใช่ → `UX-0007` (เรื่องใหม่) |
| 2. สินค้าชื่อคล้ายกันหลายเจ้า ต้องเดา | **REPRODUCED** | นับเข้า `UX-0002` เป็น run ที่สอง |

## จุดที่ติดข้อ 1 ของ agent จริง ๆ แล้วเป็นสองเรื่อง

agent เขียนรวมกันมาเป็นข้อเดียว แต่เป็นคนละต้นเหตุ:

- **หาไม่เจอ** เพราะแคตตาล็อกเป็นภาษาอังกฤษ → `UX-0001`
- **ไม่บอกว่าหาไม่เจอ** → `UX-0007` ซึ่งจะยังผิดอยู่แม้แก้ `UX-0001` เสร็จ
  เพราะพิมพ์คำที่ไม่มีจริงก็ยังเงียบเหมือนเดิม

ยืนยันเอง: พิมพ์ `มอสซาเรลล่า` ในช่องค้นหาของหน้ารับสินค้าเข้า — หน้าจอไม่เปลี่ยนอะไรเลย
กล่องด้านล่างยังเขียนว่า "ยังไม่มีรายการ — ค้นหาด้านบนเพื่อเพิ่มสินค้า"
พิมพ์ `mozzarella` แทน — ขึ้นสองรายการทันที (CHS-01-01-001, CHS-01-01-010)

หน้าสร้างใบขอซื้อในสถานการณ์เดียวกันขึ้น "ไม่พบสินค้าที่ตรงกัน" — สองหน้านี้ทำคนละอย่าง

## ข้อ 2 ทำให้ต้องแก้กติกาการรวมปัญหาซ้ำ

เรื่องนี้กับ `UX-0001` เคยถูกตั้งไว้ที่ `route: /requests` แต่ตอนนี้เจอที่ `/receive` ด้วย
ถ้าปล่อยให้ `dedupeKey` แยกตาม route จะได้ Issue ซ้ำใบต่อหน้าจอ ทั้งที่แก้ครั้งเดียวดับหมด
และจะทำให้ลำดับความสำคัญเพี้ยน เพราะปัญหาเดียวถูกนับกระจายเป็นหลายใบใบละหนึ่งครั้ง

จึงเปลี่ยนทั้งสองเรื่องเป็น `route: "*"` และเขียนกติกาลง README:
**ต้นเหตุเดียวกันหลายหน้า = ใบเดียว · อาการเหมือนกันแต่คนละต้นเหตุ = คนละใบ**

## ที่ agent ชมไว้ และตรงกับที่เห็น

- คลังปลายทางตั้งเป็น "คลังหลัก" มาให้แล้ว ไม่ต้องเลือกเอง
- เลือกสินค้าแล้วหน่วย (KG / EA) ถูกตั้งให้อัตโนมัติ
- ออกจากหน้าไปดูอย่างอื่นแล้วกลับมา ร่างยังอยู่ครบพร้อมข้อความ "บันทึกร่างไว้ในเครื่องนี้แล้ว"
  — ข้อนี้สำคัญเป็นพิเศษ เพราะการเดินอ้อมที่ `UX-0007` บังคับให้ทำ จะเสียงานทิ้งถ้าไม่มีมัน
