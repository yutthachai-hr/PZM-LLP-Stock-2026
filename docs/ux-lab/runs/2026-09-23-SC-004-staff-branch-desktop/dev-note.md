## ข้อ 2 — ตัวเลขยืนยันว่าแอปทำถูกทุกอย่าง

ตรวจยอดคงเหลือจริงหลัง run:

| คลัง | สินค้า | คงเหลือ | ควรเป็น |
|---|---|---|---|
| คลังหลัก | MOZZARELLA WHOLE MILK (FOODGALLERY) | 8 | 10 − 2 ✓ |
| คลังหลัก | FLOUR DANG (AGRICULTURE) | 3 | 4 − 1 ✓ |
| สาขาอ่อนนุช | FLOUR DANG (AGRICULTURE) | 1 | 0 + 1 ✓ |

การเบิกตัดจากคลังที่ถูก การโอนเข้าสาขาที่ถูก ไม่มีตัวเลขไหนผิดเลย

และหน้าจอเขียนบอกไว้ตรง ๆ อยู่แล้วว่า **"ตัดสต๊อกออก ไม่เพิ่มเข้าสาขาอื่น"**
agent อ่านข้อความนั้นแล้วยังคาดหวังอย่างอื่น — นั่นคือนิยามของ `TRAINING_ISSUE` ตาม README

ที่สาขาสารสินไม่มีแถวมอสซาเรลล่าเลย (ไม่ใช่ 0) ก็ถูก เพราะไม่เคยมีของตัวนั้นที่นั่น
แถวยอดคงเหลือเกิดเมื่อมีการเคลื่อนไหวจริงเท่านั้น

## ที่เหลืออยู่จริง และเป็นคำถามของเจ้าของ ไม่ใช่ของ dev

ระบบยอมให้พิมพ์ "ครัวสาขาสารสิน" ลงช่องหมายเหตุ แล้วบันทึกเป็นการเบิกจากคลังหลัก
ปลายทางที่พิมพ์ไปเป็นข้อความล้วน ระบบไม่ได้รู้จักมันในฐานะสถานที่

**คำถามที่ตอบได้คนเดียวคือเจ้าของ**: หน้างานจริง สาขาเบิกของที่ตั้งอยู่ในคลังหลักไปใช้เลยหรือเปล่า
ถ้าใช่ พฤติกรรมตอนนี้ถูกแล้วและไม่ต้องแตะอะไร
ถ้าเจ้าของคาดหวังว่าต้องเห็นร่องรอยที่สาขา ก็แปลว่าต้องโอนก่อนแล้วค่อยเบิก ซึ่งเป็นวิธีทำงาน ไม่ใช่โค้ด

**ห้ามเดาแล้วแก้** เรื่องนี้แตะ "จำนวนสต๊อก" ซึ่งเป็น `CRITICAL` ตามตารางใน README

## ที่ agent จัดว่าไม่ใช่ปัญหา และเห็นด้วย

ข้อความเดิมค้างในช่องหมายเหตุแล้วพิมพ์ทับจนต่อกันมั่ว — เป็นเพราะร่างที่ระบบเก็บไว้ให้ ซึ่งเป็นของดี
agent ไม่ได้เคลียร์ก่อนพิมพ์ ความผิดของตัวเอง

**แต่เป็นครั้งที่สองแล้วที่ร่างค้างทำให้ agent พลาดแบบนี้** (ครั้งแรกคือ SC-002 ที่รายงานผิดว่าค้นภาษาอังกฤษไม่เจอ)
ถ้าเจอครั้งที่สามให้ตั้งเป็นเรื่อง เพราะนั่นแปลว่ารูปแบบนี้ดักคนอยู่จริง ไม่ใช่ความซุ่มซ่ามของใครคนหนึ่ง
