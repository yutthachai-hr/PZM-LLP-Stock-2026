## ข้อ 2 ไม่ต้องเดาเลย ต้นเหตุอยู่ในโค้ดตรง ๆ

`record()` ใน `src/pages/purchase/SendWizard.tsx`:

```ts
await setShareStatus(order.id, status, { id: user.id, name: user.name }, version)
...
await onStatus({ ...order, shareStatus: status })
```

`setShareStatus` (`src/services/purchaseOrders.ts:330`) เขียน `sentAt = now` ลงเอกสารจริง
แต่คืนค่าเป็น `Promise<void>` ค่าที่เพิ่งเขียนจึงไม่ได้กลับมา
บรรทัดถัดมาส่งต่อสำเนา**ก่อน**เขียน โดยแก้แค่ `shareStatus`

`needsResend()` (`:470`) ตัดสินจาก `(order.sentAt ?? 0) < last.at`
`sentAt` ที่ค้างอยู่เป็นเวลาก่อนการแก้ไข จึงน้อยกว่าเวลา revision เสมอ → ป้ายค้าง

ฐานข้อมูลถูกต้องตลอด ผิดเฉพาะสำเนาบนหน้าจอ ซึ่งเป็นเหตุผลที่โหลดหน้าใหม่แล้วหาย

**ยังไม่ได้ตรวจ**: ตัวกรองแท็บที่ `src/pages/Orders.tsx:180-181` ก็เรียก `needsResend`
ใบนี้จึงน่าจะถูกนับผิดแท็บในจังหวะเดียวกันด้วย — ตรวจตอนแก้

## ข้อ 1 จริง แต่ระบบตั้งใจ

บรรทัดที่ว่างคือสินค้าอื่นของผู้ขายเจ้าเดียวกันที่เพิ่มเข้าใบได้ ซึ่งเป็นความสามารถที่ต้องมีจริง
สิ่งที่ขาดคือการบอกว่าสองกลุ่มนี้ต่างกัน จึงเป็นเรื่องของการแสดงผล ไม่ใช่ความถูกต้อง

## ที่ agent จัดให้เองว่าไม่ใช่ปัญหา และเห็นด้วย

- ช่องจำนวนขึ้นขอบแดงหลังแก้เป็น 2.5 แล้วบันทึกผ่านปกติ — น่าจะเป็นสีที่หมายถึง "แก้ไขแล้ว"
  agent เดาเองถูกและไม่นับเป็นปัญหา **แต่บันทึกไว้ตรงนี้เผื่อเจอซ้ำใน run อื่น** ถ้าเจออีกให้ตั้งเป็นเรื่อง
- ระบบเด้งกลับหน้าเลือกแบรนด์ระหว่างทาง — เป็นผลจากวิธีขับเบราว์เซอร์ของแล็บเอง ไม่ใช่ของแอป
