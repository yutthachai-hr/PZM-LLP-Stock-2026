# คำตัดสินหลัง reproduce

| จุดที่ติด | ผล reproduce | เป็น Issue ไหม |
|---|---|---|
| 1. "จำนวนในระบบ" หน้าปรับสต๊อกไม่ตรงกับหน้าสินค้าคงคลัง | **ระบบทำถูก — ทั้งสองเลขถูก** | ใช่ แต่เป็น `TRAINING_ISSUE` → `UX-0009` |
| 2. กดชื่อสินค้าแล้วเปิดฟอร์มแก้ไข | **REPRODUCED** | ใช่ → `UX-0010` |

## ข้อ 1 — สองเลขที่ไม่ตรงกันนั้นถูกทั้งคู่

ตรวจยอดจริงหลัง run:

| คลัง | สินค้า | คงเหลือ |
|---|---|---|
| คลังหลัก | MOZZARELLA WHOLE MILK (FOODGALLERY) | 7 |
| คลังหลัก | FLOUR DANG (AGRICULTURE) | **1** |
| สาขาอ่อนนุช | FLOUR DANG (AGRICULTURE) | **1** |

คำอธิบายทั้งหมดอยู่ในบรรทัดเดียว: **แป้งอยู่สองคลัง**

- หน้าปรับสต๊อก "จำนวนในระบบ" = **3** คือของที่**คลังหลัก**เท่านั้น (ก่อนปรับ) — ถูก
- หน้าสินค้าคงคลัง "คงเหลือ**รวม**" = **4** คือ 3 ที่คลังหลัก + 1 ที่อ่อนนุช — ถูก
- agent พิมพ์ "จำนวนที่นับได้ = 1" ระบบตั้งคลังหลักเป็น 1 ตรงเป๊ะ — ถูก
- หลังบันทึก หน้าสินค้าคงคลังขึ้น "รวม 2" คือ 1 + 1 — ถูก

ไม่มีเลขไหนผิดเลยสักตัว agent เอาเลขเฉพาะคลังไปเทียบกับเลขรวมสองครั้ง
แล้วสรุปว่าระบบสต๊อกเพี้ยน ซึ่งในแอปสต๊อกเป็นข้อสรุปที่อันตรายที่สุดข้อหนึ่ง

สังเกตว่าหน้าสินค้าคงคลังตั้งชื่อคอลัมน์ว่า "คงเหลือ**รวม**" ไว้ถูกต้องแล้ว
และหน้าปรับสต๊อกมีตัวเลือกคลังอยู่บนหัวฟอร์ม — ข้อมูลครบ แต่ agent ไม่ได้เชื่อมโยง

## ข้อ 2 — ทำซ้ำได้ และเป็นครั้งที่สองที่มีคนเจอ

กดชื่อ `MOZZARELLA WHOLE MILK 2.72*8 (FOODGALLERY)` ในตารางหน้าสินค้าคงคลัง
เด้งป็อปอัป **"แก้ไขสินค้า"** เต็มรูปแบบ: ชื่อสินค้า · SKU · บาร์โค้ด · หมวดหมู่ · หน่วยนับ
· หน่วยที่แสดง · สต๊อกขั้นต่ำ · ผู้ขาย · **รายการผู้ขายสำรองเป็นติ๊กบ็อกซ์ยาวเลื่อนได้** · ต้นทุน

`SC-001` ก็เจอเรื่องเดียวกันและเขียนไว้ว่า *"ตกใจนิดนึง รีบกดปิดออกมาไม่ได้แตะอะไร กลัวไปแก้ข้อมูลเขาโดยไม่ตั้งใจ"*
แต่ตอนนั้น agent จัดให้ตัวเองว่าไม่ใช่ปัญหาของระบบ — **สอง agent อิสระเจอสิ่งเดียวกัน คนละ run คนละงาน**
จึงเป็นรูปแบบ ไม่ใช่ความบังเอิญ

หมายเหตุ: หลักฐานจาก `SC-001` ใช้ได้แม้ run นั้นจะถูกตัดสินว่าใช้วัด UX ไม่ได้
เพราะข้อบกพร่องของ run นั้นคือสนามซ้อมไม่มีผู้ขาย ซึ่งไม่เกี่ยวกับเรื่องนี้เลย

## รูปแบบที่เริ่มเห็นข้ามหลาย run

`UX-0008` กับ `UX-0009` เป็น `TRAINING_ISSUE` ทั้งคู่ และทั้งคู่มีต้นตอเดียวกัน:
**พนักงานไม่ได้คิดเรื่อง "ของชิ้นนี้อยู่คลังไหน" แต่ระบบคิดตลอดเวลา**

- `UX-0008` — เบิกจากคลังไหน ปลายทางเป็นคลังหรือเป็นแค่ข้อความ
- `UX-0009` — เลขที่เห็นเป็นของคลังเดียวหรือของทุกคลังรวมกัน

ถ้ามี `TRAINING_ISSUE` เรื่องคลังโผล่อีกใน run ถัดไป ให้ถือว่าไม่ใช่เรื่องของการสอนงานแล้ว
แต่เป็นเรื่องที่ระบบเล่าเรื่องคลังให้คนฟังไม่ดีพอ แล้วยกทั้งกลุ่มเป็น `UX_FRICTION`
