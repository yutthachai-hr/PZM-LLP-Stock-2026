# Orders UX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans inline. Independent review stays with parent-owned T3 OpenCode tasks.

**Goal:** Simplify the existing Orders list without changing order operations.
**Architecture:** Pure presentation model, additive safe DataTable interactions, existing OrderSheet and RowMenu.
**Tech Stack:** Existing React, TypeScript, Tailwind, Vitest, Playwright and Firebase emulators.
**Spec:** docs/superpowers/specs/2026-10-15-orders-ux-design.md

## Global Constraints

No business eligibility, schema, rules, dashboard, credentials, cron or data-authority changes. Preserve supplier confirmation and exact current action predicates. Every final-head release gate must pass before merge. No live data tests.

## Review Focus

- Portal menu clicks and bubbling keyboard events must not open an underlying document.
- Closed-short is not full receipt; LINE sent is not supplier confirmation.
- Same IDs across brands must never retain the prior sheet or selection.
- Shared DataTable callers retain native controls and table semantics.
- Long supplier names and Thai labels fit 1024px and mobile without clipped actions.
