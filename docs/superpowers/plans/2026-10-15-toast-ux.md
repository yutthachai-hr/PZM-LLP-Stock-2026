# Toast UX implementation plan

> Use Superpowers executing-plans inline. Owner supplied the design and authorized execution. Independent review remains under T3 with at most three children; do not interrupt current tasks.

## Goal and constraints

Replace heavy transient toast blocks with restrained cards. Preserve existing success/error/info string calls and stable useToast identity. Add warning and structured title/description/action. No business logic, permission, Firestore, queue-persistence or dashboard changes.

Use existing fonts and semantic tokens. Desktop is top-right below the header, 22rem wide. Mobile is full width with inset above tabbar, form controls, demo pill and safe area; account for virtual keyboard. All four variants have readable title, optional details, icon and 44px close target. Motion is opacity/short slide with reduced-motion support.

The existing operational NotificationHost already owns the proposed corner. Use one shared visual viewport/slot so operational alerts and transient toasts cannot overlap. Keep its notification queue, severity, timers, sounds, navigation and mark-read behavior unchanged. Operational notices reserve up to three slots; transient toasts wait rather than expire unseen. Defer the optional sound prompt while three operational notices are shown. No fourth ordinary card in the visible stack.

## Review focus

- Stable API identity must not trigger Orders reload or unmount LINE wizard.
- Repeated success/error calls must not flood or extend timers indefinitely.
- Pending toasts must not expire before being displayed; error/warning need longer reading time.
- Hover, keyboard focus and hidden tab pause transient timers; focus is never stolen.
- Operational critical notification behavior must not be weakened by visual coordination.
- Shared viewport must clear counts on unmount and avoid mobile footer/keyboard collisions.
- Main CI size budget is tight; measure the final build, never weaken its thresholds.
