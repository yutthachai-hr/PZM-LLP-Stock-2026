## 0. บริบทที่ต้องรู้ก่อนแตะอะไร

**ระบบ**: Inventory Pzm — React 19 + Vite + TypeScript + Tailwind v4 + Firebase (Spark/ฟรี) · ของจริง `https://pzmstock.pages.dev`
(Firebase project `pzm-stock-x5`, **ข้อมูลจริงของบริษัท**) · เดโม `npm run demo` → `localhost:5175` (browser storage ล้วน, คนละ Firebase project)
หรือ `https://demo.pzmstock.pages.dev` (branch `demo`) · repo `github.com/yutthachai-hr/PZM-LLP-Stock-2026` · โฮสต์ Cloudflare Pages
(push `main` = deploy จริง, push `demo` = deploy เดโม; ตรวจว่าขึ้นแล้วด้วย `curl -s https://pzmstock.pages.dev/ | grep -o 'index-[^"]*\.js'` เทียบกับ `dist/`)

**สองแบรนด์ในฐานเดียว**: Pizza Mania (collection ชื่อตรง เช่น `products`) และ Le Lapin (prefix `lelapin__`) — `backend.forBrand(getBrand())`
ทุกหน้าต้องใช้ได้ทั้งสองแบรนด์ สีแบรนด์มาจาก `BrandDef` runtime — **ห้าม hardcode สีแดง** ใช้ token `--color-brand*`

**สามขนาดจอมีอยู่แล้ว** (`src/lib/viewport.ts`: phone <768 / tablet 768–1279 / desktop ≥1280) — phone = แถบแท็บล่าง + ActionSheet + QtySheet + การ์ดแทนตาราง,
tablet = NavRail, desktop = sidebar 256px (`src/components/Layout.tsx`, `nav/`). spec เดิม `docs/superpowers/specs/2026-09-21-mobile-tablet-ui-design.md`
**รอบนี้ไม่รื้อโครงสามขนาดนั้น** — เอา "ภาษาภาพ" ใหม่ไปใส่ทั้งสามขนาด

**กติกาเจ้าของที่ห้ามละเมิด** (ครบใน `HANDOFF.md` §7):
- **"อย่าเปลี่ยนแปลงข้อมูลใดใดโดยไม่ถามก่อนเด็ดขาด"** — ห้ามแก้ข้อมูลใน `pzm-stock-x5` โดยไม่ได้รับคำสั่งเฉพาะเจาะจงวันนั้น
- ทดสอบใน demo ก่อนเสมอ; ห้ามกดปุ่มอ่านทั้ง collection (ตรวจความสอดคล้อง/คำนวณใหม่/สำรอง) ซ้ำ ๆ บนของจริง (โควตาอ่าน 50k/วัน รีเซ็ต ~14:00)
- **listener แบบ real-time เปิดได้สูงสุด ~7** — ตอนนี้ใช้ไปแล้ว 8 ตัว (products, locations, stockLevels, movements(90 วัน), minOverrides, users(admin), notifications, entryUnits + profile) → **ห้ามเพิ่ม listener ใหม่** ของใหม่ต้องอ่านแบบ `getRange` + cache (`src/data/rangeCache.ts`)
- rules มีงบ 1,000 expression ต่อ request (ดู `tests/firestore-rules.test.ts` budget test) — เพิ่มฟิลด์ต้องนับ
- **deploy `firestore.rules` ก่อน push โค้ดที่เขียนฟิลด์ใหม่** (ไม่งั้นแอปจริงเขียนไม่ได้) และการ deploy rules ต้องให้เจ้าของยืนยันใน chat ทุกครั้ง (`npx firebase deploy --only firestore:rules --project pzm-stock-x5`; ถ้า token หมดอายุ เจ้าของรัน `npx firebase login --reauth` เอง)
- ไม่ใช้ SaaS เสียเงิน, ไม่มี LINE OA/bot, ไม่ `npm audit fix --force`, ไม่ commit secrets, SKU ต้องตรง Excel บริษัท
- ด่านก่อน commit: `npx tsc -p tsconfig.app.json --noEmit && npm run lint && npm run i18n:check && npm test && npm run test:rules && npx tsc -p worker/tsconfig.json --noEmit && npm run build`
  (`npm run test:rules` ต้องมี Java; i18n: ทุกข้อความไทยต้องผ่าน `t('…')` และมีคู่อังกฤษใน `src/i18n/en.ts` — `t()` ยาว ๆ ห้ามตัดบรรทัด, key ใน en.ts ใช้ single quote)
- ไฟล์ใน repo เป็น CRLF — ถ้าแก้ด้วย script ใช้ `newline=''`

**การตัดสินใจของเจ้าของสำหรับรอบนี้ (22 ก.ย.)**:
1. ทำ **ทั้งหน้าตาและฟีเจอร์ใหม่ในภาพ** (ไม่ใช่แค่ restyle)
2. **ไม่มีขั้นอนุมัติ** สำหรับปรับสต๊อก/โอนสาขา — บันทึกแล้วมีผลทันทีเหมือนเดิม (สถานะ "รออนุมัติ" ในภาพตัดทิ้ง)
3. เอา **สแกนบาร์โค้ด** และ **กล่องข้อความภายใน** (ไอคอนแชท) · **ไม่เอา** ปุ่ม "คู่มือการใช้งาน"

## 2. หน้าต่อหน้า — ภาพ vs ข้อมูลจริง และสิ่งที่ต้องสร้าง

> รูปแบบ: **ในภาพ** → **ข้อมูลจริงที่มี** → **ต้องสร้าง**. สิ่งที่ "ตัดทิ้ง" คือของในภาพที่เจ้าของตัดสินใจไม่เอาหรือระบบไม่มีทางมี

### 2.1 ภาพรวม (Dashboard) — `src/pages/Dashboard.tsx` (desktop/tablet), `PhoneHome.tsx` (phone)
- ในภาพ: ทักทาย "สวัสดีครับ คุณ AA" + วันที่; StatRow 5 ใบ (รับเข้าวันนี้, รอออนุมัติใบสั่งซื้อ, สินค้าคงเหลือน้อย, รอโอน/โอนสาขา, มูลค่าสินค้าคงคลัง) แต่ละใบมีบรรทัดเทียบ + ลูกศรลิงก์; กราฟแท่ง "ความเคลื่อนไหว (รายสัปดาห์)" รับเข้า/จ่ายออก/โอนย้าย 7 วัน; ตาราง "สินค้าคงเหลือน้อย" (รูป, ชื่อ, SKU, คงเหลือชิปสี, หน่วย, ขั้นต่ำ); "ภาพรวมสาขา" (สาขา, สินค้าทั้งหมด, ใกล้หมด, มูลค่า, สถานะ); "กิจกรรมล่าสุด" timeline; "เมนูด่วน" 6 ปุ่ม
- ข้อมูลจริง: มีครบใน `useData()` (movements 90 วัน, levels, products+cost, minFor); PO/PR จาก `orderCache`/`requestCache`; "สาขา" = `locations` (คลังหลัก/สาขาสารสิน/สาขาอ่อนนุช) **ไม่ใช่ชื่อผู้ขายอย่างในภาพ**; "รอโอน" ไม่มี (ไม่มีขั้นอนุมัติ) → ใบนี้เปลี่ยนเป็น **"โอนสาขาวันนี้"** (นับ IS- ที่เป็น transfer วันนี้)
- ต้องสร้าง: `lib/stats/periodCompare.ts` — คำนวณ "เทียบช่วงก่อน" จาก ledger ที่โหลดอยู่ (วันนี้ vs เมื่อวาน, 30 วันนี้ vs 30 วันก่อน; มูลค่าเมื่อ 30 วันก่อน = มูลค่าปัจจุบัน − Σ(cost×Δqty ของ movement ตั้งแต่วันนั้น)) **ซ่อนบรรทัดเทียบเมื่อ ledger window ไม่ครอบคลุม** (`RECENT_DAYS`=90); `charts/WeeklyMovementChart`; `BranchOverview` (ต่อ location: จำนวน SKU ที่มีของ, ใกล้หมด, มูลค่า, สถานะ = ปกติ/มีสินค้าใกล้หมด); `RecentActivity` (10 รายการล่าสุดจาก movements+PO+PR รวมเรียงเวลา); `QuickMenu` (ลิงก์ตาม role: รับเข้า, สั่งซื้อใหม่, โอนสาขา, ปรับสต๊อก, รายงาน, นำเข้า Excel)
- phone: `PhoneHome` เดิมรับ StatTile 2 คอลัมน์ + สินค้าใกล้หมด 5 แถว + เมนูด่วน; ไม่แสดงกราฟรายสัปดาห์และภาพรวมสาขาบนโทรศัพท์ (เจ้าของขอให้หน้าแรกมือถือ "ดูง่าย สบายตา" 21 ก.ย.)
- ตัดทิ้ง: dropdown เลือกวันที่มุมขวาบน (ภาพรวมคือ "วันนี้" เสมอ)

## 3. ฟีเจอร์ใหม่: สแกนบาร์โค้ด

- ฟิลด์ `barcode?: string` บน `Product` (ไม่บังคับ; ตรวจไม่ซ้ำภายในแบรนด์ตอนบันทึก) → rules `validProduct` เพิ่ม `'barcode'` ใน hasOnly + `is string && size() <= 64`
- แก้ได้ที่: ฟอร์มสินค้า (ช่องใหม่ + ปุ่ม "สแกนเพื่อกรอก"), นำเข้า Excel (คอลัมน์ `Barcode` ถ้ามี — `src/services/import*`; SKU ยังเป็นกุญแจหลัก), เมนู ⋮ ในตารางสินค้า
- ค้นหา: `looseMatch` ใน LineBuilder/ProductPicker/แถบบน เพิ่ม `p.barcode` เข้า field ที่ค้น; สแกนได้ตรง = เพิ่มแถวทันที (ไม่ต้องกดเลือก)
- ตัวสแกน `src/components/BarcodeScanner.tsx`: เปิดกล้องด้วย `getUserMedia` → ใช้ `BarcodeDetector` ของเบราว์เซอร์ถ้ามี (Chrome/Android) ไม่งั้น fallback **`@zxing/browser`** (MIT) — โหลดแบบ `lazy()`; รองรับ EAN-13/EAN-8/Code128/QR; ปิดกล้องเมื่อปิด modal เสมอ; ถ้าไม่มีกล้อง/ไม่อนุญาต แสดงข้อความและช่องพิมพ์เลขแทน
- ที่ปุ่มโผล่: ช่องค้นหาของ รับเข้า/เบิก-โอน/ปรับสต๊อก/ขอซื้อ (ไอคอนบาร์โค้ดท้ายช่อง), และ phone QtySheet
- ทดสอบ: unit สำหรับการค้นด้วย barcode และการกันซ้ำ; rules test ฟิลด์ใหม่; ทดสอบกล้องจริงบนมือถือของเจ้าของ (ผมทำไม่ได้ในเบราว์เซอร์ pane)
- ก่อนใช้จริงเจ้าของต้องกรอกบาร์โค้ดสินค้า 300+ ตัว (ผ่าน Excel) — เขียนเตือนไว้ใน HANDOFF

## 4. ฟีเจอร์ใหม่: กล่องข้อความภายใน (ไอคอนแชท)

**เป้าหมาย**: โน๊ตถึงกันระหว่างพนักงานในแบรนด์ (เช่น "ของ FOODGALLERY มาบ่ายนี้") — ไม่ใช่แชท real-time, ไม่แทน LINE

- collection ใหม่ `messages` (+ `lelapin__messages`): `{ id, body (≤1000), byUserId, byUserName, createdAt, mentions?: string[] (uid), pinned?: boolean }` — เพิ่มใน `staffWritable` + `validMessage` (create เท่านั้น; แก้ไม่ได้; ลบได้เฉพาะเจ้าของข้อความหรือแอดมิน; `byUserId == request.auth.uid`) + `ALL_COLLECTIONS` ใน `services/backup.ts` + memory backend ในเทสต์
- **ไม่มี listener**: อ่านด้วย `getRange('createdAt', since, now)` ผ่าน `rangeCache` เมื่อเปิดกล่อง (14 วันล่าสุด, "โหลดเพิ่ม" ย้อนหลัง) และ refresh ทุก 5 นาที **เฉพาะตอนกล่องเปิดอยู่**; ส่งข้อความ = `add` + `noteWritten` (overlay ทันทีเหมือน recentWrites)
- ตัวเลขยังไม่อ่าน: ฟิลด์ใหม่ `messagesReadAt?: number` บน `users/{uid}` — **ขยาย rules self-update branch ที่ deploy 22 ก.ย.** จาก `hasOnly(['name'])` เป็น `hasOnly(['name','messagesReadAt'])` (+ `is number`); badge = จำนวนข้อความที่ `createdAt > messagesReadAt` **นับจาก 1 query เมื่อโหลดแอป** (ไม่ใช่ listener) และหลังส่ง/เปิดกล่อง; เปิดกล่อง = เขียน `messagesReadAt = now` (1 write)
- UI: ปุ่มไอคอนข้อความในแถบบน (badge แดง) → แผงเลื่อนจากขวา (desktop/tablet ใช้ `Modal side`) / เต็มจอ (phone); รายการข้อความเรียงใหม่→เก่า, avatar ตัวอักษร, เวลา, ปุ่มปักหมุด (admin/หัวหน้า), ช่องพิมพ์ล่าง + ส่ง; @ชื่อ = เลือกจาก `users` (แอดมินเท่านั้นที่โหลด users — พนักงานทั่วไปพิมพ์ธรรมดา ไม่มี @)
- **ไม่ทำ**: แจ้งเตือน push, อ่านแล้ว/ยังไม่อ่านรายคน, ไฟล์แนบ, ลบ/แก้ข้อความหลังส่ง (ยกเว้นลบของตัวเอง)
- ทดสอบ: rules (create ของตัวเอง/ปลอมชื่อคนอื่นไม่ได้/ลบของคนอื่นไม่ได้/แอดมินลบได้/ยาวเกินไม่ได้), unit สำหรับ unread count และ cache window
