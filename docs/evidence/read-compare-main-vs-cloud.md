## คำแนะนำสำหรับการรวม

**เก็บชั้นข้อมูลของ main** เพราะดีกว่าเกือบทุกแถวและขึ้นจริงแล้วพร้อม rules + indexes:
- `src/data/syncedCollection.ts`, `syncedList.ts`, `deviceStore.ts`
- `rangeCache.ts` (อ่านเฉพาะช่วงที่ขาด + delta + เก็บในเครื่อง)
- `notificationInbox.ts` (เฉพาะผู้รับ)
- `readMeter.ts` (มาตรวัดเดียวที่ประเมินค่าที่ถูกคิดเงินได้)

**ยกจาก cloud มาใช้:**
- **D6'** DataTable วาด layout เดียวพร้อมแบ่งหน้า (หน้าสินค้า 80 → 40)
- **D1'** โหลดหน้าเมื่อเปิดครั้งแรก (main 1,209 KB → 223 KB) ซึ่ง main ยังไม่มี
- ส่วนอื่นที่ไม่ใช่ชั้นอ่านข้อมูล: ADR-001, Phase B–G, outbox

**ข้อควรระวังตอนรวม:**
- `useLive` ของ cloud มี option `cache` ของตัวเอง ห้ามใช้คู่กับ `useSynced` ของ main บน collection เดียวกัน (products, stockLevels) เพราะจะกลายเป็นสอง listener
- Exception Inbox / C5 ของ cloud อ่าน `data.notifications` ซึ่ง main เปลี่ยนเป็นเฉพาะผู้รับแล้ว ต้องตรวจว่าการแจ้งเตือนที่ Inbox ต้องการยังมาถึง

## เกณฑ์ผ่านของ branch ที่รวมแล้ว

รัน `e2e/read-compare.spec.ts` บน branch ที่รวม แล้วต้องได้:
1. ทุกแถว **billed ≤ ของ main** (ยกเว้นหน้าสินค้าที่ควรลดลงเหลือ ~40)
2. ไม่มี listener งอก (จำนวน listener คงที่)
3. `npm test`, `test:rules`, `test:e2e`, build ผ่านทั้งหมด
